# AD-146 — gates are verdicts about a tree; hooks read them and never wait for a suite

- **status**: active

## Decision

1. **A gate outcome is a verdict about a tree.** `recordShipVerdict` (`src/core/gate/gate.verdicts.ts`) stores
   the gate, its command, the tree id, the result, its duration, an output tail and its source — a session key
   or `verify`. The store lives in the main checkout's state directory, so linked worktrees share it.
2. **The tree id is computed without touching the repository.** `workingTreeId` and `headTreeId`
   (`src/platform/git.ts`) build the tree in a scratch index and a scratch object directory with the real object
   database as an alternate. The scratch index keeps the original index's mtime, so a same-size edit inside the
   racy-git window is still re-read. Files git cannot index are skipped rather than losing the id. The harness's
   own directory is excluded from both ids, so its lessons and state never invalidate a verdict.
3. **The push battery never runs a gate.** For `push`, `pr-open` and `pr-merge` it requires the gates owed by the
   code the turn changed plus every code change on the branch that is not on the remote's default branch, and a
   passing verdict for the tree of `HEAD` — the commit that ships. A failing verdict refuses with its output; a
   verdict recorded only over uncommitted changes refuses as `ship-gate-uncommitted` and names the files; no
   verdict refuses as `ship-gate-unverified` and names `tlc harness verify`. A push with nothing ahead of its
   upstream owes nothing. A command that also commits ships the working tree it is about to commit, so the
   verdict is looked up for that tree instead of `HEAD`.
4. **`tlc harness verify` produces verdicts** by running the configured gates in the agent's own shell, where no
   hook timeout applies. A gate that changes the tree while it runs is not recorded.
5. **The stop grind reuses and bounds.** It reuses a verdict for the current tree recorded by its own session or
   by `verify` — never another session's, as [/decisions/ad-137.md](/decisions/ad-137.md) requires — and
   otherwise runs within a 90-second budget. A timeout ends the whole process group. A suite that does not fit
   is handed back with an instruction to run `verify`; the overrun is kept as a lower-bound estimate, never as a
   verdict.

## Why

The hosts decide this, not taste. Cursor's permission hooks fail closed and its hook runner treats a killed
process as a failure; Claude Code lets a timed-out pre-tool hook through. Neither has a blocking asynchronous
mode. A gate that cannot finish inside the hook therefore either blocks every ship or protects nothing. Measured
on the reporting machine: the push hook started at 11:52:39, the cached lint passed at 11:52:40, the test gate
was still running when the host gave up nine seconds later, and the push was refused.

Keying on a tree makes the verdict a fact about content, which is what lint and tests are: the same tree and
command give the same answer whoever asks. Keying on `HEAD` for a ship is what CI does — the uncommitted state
of a working copy is not what reaches the remote, so a verdict over it cannot clear one.

Scoping the battery to the turn alone let a push in a later turn ship code no gate had seen; measured on the
reporting machine, a push and a PR went out at 12:48 with no verdict recorded at all.

## Trade-offs

A ship from a dirty working copy needs the changes committed, stashed or ignored before `verify`. That is
friction, and it is the friction CI already imposes. A suite slower than the stop budget is verified by an
explicit command instead of automatically, which costs one instruction per turn and removes every silent skip.

## Not decided here

- Running a suite that does not fit the stop budget in the background on its own. The hosts give no channel to
  report its result back into the turn, so the explicit `verify` stays the way to get a verdict.
- What CI runs. A local verdict gates the agent's ship; the remote's own checks remain the final authority.
- Signing or sharing verdicts between machines. The record is local to the checkout and its worktrees.
